# Domain docs

Read `CONTEXT.md` for the project's vocabulary and the relevant decisions in `docs/adr/` before exploring an area of the code.

Use glossary terms in issues, proposals, test names and documentation. If a concept is missing, check whether an existing term fits before proposing a glossary addition.

If a proposal conflicts with an ADR, name the decision and explain why it should be revisited. If a document is missing, continue with the available context.
